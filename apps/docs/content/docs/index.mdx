BugBerry is a browser extension and a server. Someone who finds a bug clicks the BugBerry icon, takes a screenshot or records the screen, and sends a report. The report already holds what a developer would otherwise have to ask for: the console, the network requests, the clicks and keys that led there, and details about the browser and the page.

<Screenshot src="/screenshots/dashboard/report.png" alt="A report in the dashboard: the recording on the left, and the console it caught on the right, with the failed payment and its 500 responses" />

BugBerry is open source (AGPL-3.0). You can run it on your own server, or use the cloud at [bugberry.yuisalabs.com](https://bugberry.yuisalabs.com).

## How a report travels

1. **Capture.** The extension takes a screenshot or records a tab, a window, or the whole screen. While it does, it collects the console, the network requests, and the user's actions from the page.
2. **Review.** Before anything is sent, the reporter sees the video or screenshot, the errors and failed requests that were caught, and a suggested title. They can annotate, retake, or keep the draft for later.
3. **Send.** The report goes to your BugBerry server, into a workspace and, if you like, a project.
4. **Work on it.** Your team opens it in the dashboard: the video plays next to a timeline of events, and comments, status, priority, and assignee keep track of it.
5. **Pass it on.** Share it with a link, send it to GitHub Issues, GitLab, Linear, Jira, Plane or ActiveCollab, or let an AI agent read it through MCP.

## How the server fits together

A self-hosted BugBerry is a Docker Compose project:

```text
browser / extension
        │  https
        ▼
  Caddy (optional) ──── or your own reverse proxy
        │
        ▼
  client  nginx: the dashboard, and /api passed on to the api
        │
        ▼
  api     Bun: sign-in, reports, uploads, integrations, MCP
        │
        ├── Postgres  reports, users, workspaces
        └── storage   screenshots, videos, and captured data:
                      a local volume, or S3 / R2 / MinIO / RustFS
```

Only the `client` container opens a port, and by default only on localhost. The browser, OAuth callbacks, and the extension all see a single address.
