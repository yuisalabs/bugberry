---
title: Troubleshooting
description: Problems people run into, and how to fix them.
---

Start with the logs:

```bash
docker compose logs -f api
```

The server checks its settings on start. When one is wrong, the `api` container stops with a message naming it.

## The smoke test fails "forged X-Forwarded-For"

You ran it against `http://localhost:3000` with `TRUST_PROXY=true`. The localhost port goes around your proxy, so the check is expected to fail there. Run it against the public address. That check also uses up the share-link allowance for your IP for one minute, so wait a minute before running it again.

## The api doesn't start: "Enable at least one sign-in method"

No sign-in method is configured. Set a Google, GitHub, or GitLab client ID and secret, or `EMAIL_DRIVER`. In production, email sign-in needs a real mail service; see [Sign-in methods](/self-host/sign-in).

## Uploads fail right after they finish

With a bucket behind Cloudflare, the cache answers the server's check on the new file. Add a Cache Rule that bypasses the cache for the bucket's hostname. See [A bucket behind Cloudflare](/self-host/storage#a-bucket-behind-cloudflare).

## Long recordings fail to upload behind Cloudflare

Cloudflare limits request bodies to 100 MB on most plans. Set `MAX_UPLOAD_MB=95`, so the extension stops recording before it reaches the limit.

## Reports open, but the console and network tabs stay empty

The bucket has no CORS rule for your `APP_URL`, so the dashboard can't read the captured data. Apply `deploy/bucket-cors.json` with your address; see [The CORS rule](/self-host/storage#the-cors-rule). The browser's developer console shows a CORS error when this is the cause.

## The extension can't connect to the server

- Check that `EXTENSION_ID` matches the extension people use. A server set up for your own build rejects the store extension, and the other way round.
- Check that the person is signed in to the dashboard in the same browser.
- `APP_URL` must be HTTPS outside localhost.

## Google sign-in says "redirect_uri_mismatch"

The redirect URI in Google must be exactly `<APP_URL>/api/auth/callback/google`, with the same scheme and no trailing slash. The same goes for GitHub and GitLab with their own paths.

## After changing `ENCRYPTION_KEY`, trackers stopped working

Tokens saved with the old key can't be read. Save the token again in each integration, or put the old key back.
