## Upgrades

```bash
git pull && docker compose up -d --build --remove-orphans
docker image prune -f
```

New database migrations run when the `api` container starts. `docker stop` gives requests in progress 60 seconds to finish, so a large upload isn't cut off.

If you build the extension yourself, update the server first, then share the new extension zip.

## Maintenance mode

For planned work (a database upgrade, a move to another server), show your team a maintenance page instead of errors. Put a `maintenance.json` in the `maintenance` folder next to `docker-compose.yml`:

```bash
mkdir -p maintenance && cp docker/maintenance.example.json maintenance/maintenance.json
```

```json
{
  "code": "maintenance",
  "message": "We're moving BugBerry to a bigger server. Everything you've captured is safe.",
  "until": "2026-10-24T14:30:00Z"
}
```

From that moment every request to the api answers `503` with this notice, and the dashboard shows its maintenance page with your `message` and, when `until` is set, the time it should be back (in each person's own time zone). `code` must stay `"maintenance"`; `message` and `until` are optional. The extension tells anyone sending a report that BugBerry is down for maintenance.

Delete the file to end it. Neither step needs a restart. The public pages and the docs stay up throughout.

If BugBerry is down without maintenance mode on, the dashboard says it can't be reached and offers to try again.

### Upgrading to workspace integrations

From this version, accounts and channels are connected once per workspace and projects use them. On upgrade, every existing integration becomes a connection of its own, named after what it pointed at (such as "GitHub · kantor/web"), used by the project it belonged to, with the same target, labels and auto-send. Nothing stops sending.

Integrations that used the same token become separate connections; nothing merges them for you. To tidy up, rename the connections under **Integrations**, then in each project use the one you keep and remove the others.

## Backups

Data lives in two volumes: `fdebag-prod_pgdata` (the database) and, with local storage, `fdebag-prod_uploads` (the files). Back up both:

```bash
docker compose exec -T postgres pg_dump -U fdebag fdebag > fdebag-$(date +%F).sql
docker run --rm -v fdebag-prod_uploads:/data:ro -v "$PWD":/backup alpine tar czf /backup/uploads-$(date +%F).tar.gz -C /data .
```

With a bucket, back up the bucket with your provider's tools instead of the `uploads` volume. Keep a copy of `.env` too: without `ENCRYPTION_KEY`, the saved tracker tokens can't be read.

## Restore

Into a new installation, while its database is still empty (before anyone creates a report):

```bash
docker compose exec -T postgres psql -U fdebag -d fdebag < fdebag-<date>.sql
docker run --rm -v fdebag-prod_uploads:/data -v "$PWD":/backup alpine tar xzf /backup/uploads-<date>.tar.gz -C /data
```

## API tokens for automation

For scripts and bot accounts. The extension doesn't use tokens, and the dashboard doesn't create or show them:

```bash
docker compose exec api bun apps/api/scripts/create-token.ts --email bot@example.com --name "Bot"
```

## Previews for older screenshots

Screenshots sent before the extension made previews show the full image on every card, which makes the report list slow to scroll. This makes a small preview for each of them. The first command only lists them; the second adds the previews:

```bash
docker compose exec api bun apps/api/scripts/backfill-thumbnails.ts
docker compose exec api bun apps/api/scripts/backfill-thumbnails.ts --apply
```

It's safe to run again: a second run only looks at screenshots that still have no preview. Older videos keep showing "No preview".

## Notes for older installations

- **From the single-container version:** `--remove-orphans` removes the old `fdebag` container, which still holds port 3000. Volumes and data are not touched.
- **Upgrading to workspaces:** existing data moves into one workspace named after the most common email domain, and existing admins become its admins. Reports that were "internal" become the **Workspace** level; public reports stay public. `ADMIN_EMAILS` is no longer used: admins are set per workspace on the **Members** page, and new employees are invited from there.
- **Upgrading to the token-free extension:** this update revokes all existing API tokens. Replace the extension on your team's computers at the same time as the server; old extensions are rejected. Create new tokens for automation with `create-token.ts`.
